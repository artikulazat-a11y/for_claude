# Эмулятор ПС 110/10 кВ — OPC UA сервер

Имитатор двухтрансформаторной подстанции 110/10 кВ для отладки SCADA и мнемосхем.
Отдаёт по OPC UA **143 тега**: измерения меняются как на реальной подстанции,
команды из SCADA исполняются с учётом времени хода приводов и блокировок, уставки
записываются клиентом и сохраняются между перезапусками. Десять счётчиков
электроэнергии накапливают показания для трендов и анализа потребления.

## Однолинейная схема

```
          ВЛ-110 кВ №1                          ВЛ-110 кВ №2
               │  VL1.U                              │  VL2.U
              ─┴─ VL1.DS  линейный разъединитель    ─┴─ VL2.DS
               │                                     │
              [■] VL1.CB  выключатель 110 кВ        [■] VL2.CB
               │                                     │
              (Wh) Meter.T1  учёт 110 кВ            (Wh) Meter.T2
               │                                     │
            ( T1 )  ТДН-16000/110/10, РПН         ( T2 )
               │    АРНТ, обдув, термомодель         │
              (Wh) Meter.In1  учёт ввода            (Wh) Meter.In2
              [■] Sec1.InCB  вводной 10 кВ          [■] Sec2.InCB
               │                                     │
 1 СШ 10 кВ ━━━┿━━━━━┯━━━━━┯━━━━━[■]━━━━━┯━━━━━┯━━━━━┿━━━━ 2 СШ 10 кВ
   Sec1.U      │     │     │    SecCB    │     │     │    Sec2.U
              [■]   [■]    │  СВ + АВР   │    [■]   [■]
              (Wh)  (Wh)  (Wh)          (Wh)  (Wh)  (Wh)
               F1    F2   Aux1          Aux2   F3    F4
             Ф-101 Ф-102 ТСН-1         ТСН-2 Ф-201 Ф-202
```

`(Wh)` — счётчики электроэнергии, см. [Учёт электроэнергии](#учёт-электроэнергии).

Нормальный режим: оба ввода 110 кВ и оба трансформатора в работе, секции 10 кВ
питаются раздельно, СВ отключён, АВР введён.

## Быстрый старт

### Готовый exe для Windows (Python не нужен)

1. Скачайте **SubstationEmulator.exe** со страницы
   [Releases](https://github.com/artikulazat-a11y/for_claude/releases/latest).
2. Запустите двойным щелчком. Откроется консоль с журналом событий и
   подключений клиентов («Клиент подключился: 192.168.1.20:51234»).
   Закрытие окна или Ctrl+C останавливает сервер.
3. Уставки и показания счётчиков сохраняются в `setpoints.json` рядом с exe.

Параметры можно передать через ярлык или командную строку:
`SubstationEmulator.exe --port 4841 --time-scale 60`.

Exe не подписан цифровой подписью, поэтому Windows SmartScreen при первом
запуске может показать «Система Windows защитила ваш компьютер»: нажмите
«Подробнее» → «Выполнить в любом случае». Брандмауэр спросит разрешение на
сетевой доступ: разрешите, если SCADA работает на другом компьютере.

Exe собирается автоматически (GitHub Actions, `.github/workflows/build-exe.yml`)
при каждом изменении кода. Перед публикацией в Releases прогоняются тесты,
а сам exe запускается и проверяется OPC UA клиентом. Собрать exe у себя можно
скриптом `packaging\build_exe.bat` (нужен Python).

### Из исходников

Нужен Python 3.10 или новее (на Windows при установке отметьте «Add Python to PATH»).

```bash
pip install -r requirements.txt
python -m substation_emulator
```

На Windows можно просто запустить `run_emulator.bat`: он поставит зависимости
и запустит сервер.

Адрес сервера: **`opc.tcp://<IP-компьютера>:4840/substation/`**.
Безопасность: `None`, вход анонимный. На Windows разрешите входящие соединения
на порт 4840 в брандмауэре, если SCADA работает на другом компьютере.

Для проверки удобен бесплатный клиент **UaExpert** (Unified Automation):
Add Server → Custom Discovery → `opc.tcp://localhost:4840/substation/` →
Security None. Теги лежат в `Objects → Substation`.

## Адресация тегов

* Namespace URI: `urn:substation-emulator` (индекс **2**).
* NodeId строковый и совпадает с путём тега: `ns=2;s=T1.AVR.Uset`, `ns=2;s=F1.CB.State`.
* У каждой переменной есть Description на русском, а у аналоговых ещё
  свойства `EngineeringUnits` и (у уставок) `EURange`.

### Типы доступа

| Доступ | Что это | Поведение |
|---|---|---|
| **R** | Измерение / состояние | Только чтение. Запись → `BadNotWritable` |
| **W** | Уставка / режим | Чтение и запись. Значение вне диапазона → `BadOutOfRange`, значение не меняется. Уставки сохраняются в `setpoints.json` |
| **CMD** | Команда | Клиент пишет `true`, эмулятор исполняет команду и сам сбрасывает тег в `false` (импульс) |

Числовые уставки принимают любой числовой тип (Int16/Int32/Float/Double):
значение приводится к Double.

### Положение коммутационных аппаратов (`*.State`, Int32)

| Значение | Положение | Когда бывает |
|---|---|---|
| 0 | Промежуточное | Привод в движении: у выключателей ~0,1 с, у разъединителей 110 кВ ~6 с |
| 1 | Отключен | |
| 2 | Включен | |

## Что моделируется

* **Нагрузка фидеров** идёт по суточным графикам разных потребителей:
  жилой сектор (пики утром и вечером), завод (дневная смена, в выходные вдвое
  меньше), торговый центр. Сверху накладывается «живой» шум, cos φ плавает.
  Нагрузка зависит от напряжения: при работе РПН мощность немного меняется.
  Потребление меняется по сезонам: жилой сектор в январе примерно на треть
  больше, чем в июле (отопление, освещение), торговый центр на 10–15%,
  завод почти не меняется.
* **Напряжение 110 кВ** медленно гуляет вокруг 116 кВ и проседает в часы пиков.
  Частота держится около 50 Гц с отклонениями ±0,02 Гц.
* **Трансформаторы** рассчитываются по схеме замещения ТДН-16000/110/10
  (uк = 10,5%, Pк = 85 кВт, Pх = 18 кВт). От нагрузки считаются потери
  и падение напряжения, от положения РПН — коэффициент трансформации
  (±9 × 1,78%).
* **АРНТ**: если напряжение вышло из зоны нечувствительности дольше выдержки,
  РПН переключается на одну ступень (ход около 5 с). АРНТ блокируется при
  КЗ (U < 0,8·Uуст) и при токе выше 1,5·Iном.
* **Тепловая модель** по ГОСТ 14209 / МЭК 60076-7. Масло нагревается
  с постоянной времени 2,5–3 часа (оперативно это видно с `--time-scale 60`),
  обмотка — около 7 минут. Температура воздуха зависит от сезона и времени
  суток. Обдув включается по температуре масла (уставка) или по нагрузке
  ≥ 90% дольше 60 с.
* **КЗ на фидере** (`Fx.SimFault`): ток 2–4,4 кА в зависимости от
  удалённости места КЗ (выбирается случайно при каждой имитации).
  Напряжение на секции проседает до 40–75% от нормального.
  МТЗ отключает выключатель с заданной выдержкой.
* **Холодная нагрузка**: после восстановления питания ток фидера на 25–60%
  выше обычного и спадает за 1–2 минуты. Чем дольше не было питания,
  тем больше бросок. Зимой в вечерний максимум после долгого перерыва
  бросок у жилых фидеров может превысить уставку МТЗ и отключить фидер,
  как бывает в жизни. Если это мешает, поднимите `Fx.Prot.Iset`.
* **АВР 10 кВ**: при потере питания секции (обесточен её трансформатор),
  если на соседней секции есть напряжение, через выдержку отключается ввод
  и включается СВ. АВР однократный, повторно готов после квитирования.
* **Собственные нужды** питаются от ТСН-1 и ТСН-2: защиты и связь,
  подзаряд ЩПТ, освещение (ночью), обогрев ЗРУ и приводов (растёт в мороз),
  вентиляторы обдува трансформаторов. Летом днём это около 16 кВт,
  в мороз 40–60 кВт. Нагрузка делится между ТСН поровну, а при потере
  одной секции целиком переходит на другой ТСН.
* **ЩПТ**: при потере обеих секций батарея переходит с подзаряда (232 В)
  на разряд, обдув и привод РПН без собственных нужд не работают.
* **Счётчики электроэнергии**: см. следующий раздел.

### Оперативные блокировки

Если команда отклонена, аппарат остаётся на месте, а причина попадает
в `Station.LastEvent` и в OPC UA событие.

* `Station.RemoteMode = false` (местный режим): все команды из SCADA отклоняются.
* Разъединитель 110 кВ нельзя переключать при включённом выключателе своей ячейки.
* Параллельная работа Т1 и Т2 запрещена: нельзя включить СВ при двух
  включённых вводах 10 кВ и нельзя включить ввод при включённых СВ и соседнем вводе.
* Команда аппарату в движении или уже в заданном положении отклоняется.
* РПН «Прибавить/Убавить» принимается только при `Tx.AVR.Auto = false`.
* Включение фидера на неснятое КЗ разрешено, но МТЗ сразу отключит его снова.

### Журнал событий

Все события (переключения, срабатывания защит, АВР, изменения уставок,
отклонённые команды) публикуются двумя способами:

* **OPC UA Events** на объекте `Server` (BaseEventType; Severity: 200 —
  информация, 500 — предупреждение, 800 — авария). Подходит для окна событий SCADA.
* Строковый тег `Station.LastEvent` содержит последнее событие.

## Учёт электроэнергии

Десять счётчиков стоят так, чтобы баланс замыкался на каждом уровне:

| Счётчик | Где стоит | Что считает |
|---|---|---|
| `Meter.T1`, `Meter.T2` | Трансформаторы, сторона 110 кВ | Приём энергии на ПС |
| `Meter.In1`, `Meter.In2` | Вводы 10 кВ (после трансформатора) | Энергию, отданную трансформатором на шины 10 кВ |
| `Meter.F1` … `Meter.F4` | Фидеры 10 кВ | Отпуск потребителям |
| `Meter.Aux1`, `Meter.Aux2` | ТСН-1, ТСН-2 | Собственные нужды подстанции |

У каждого счётчика два тега:
* `Aplus` — активная энергия, приём (A+), кВт·ч;
* `Rplus` — реактивная энергия, приём (R+), квар·ч.

Обратного перетока в этой схеме нет, поэтому A− и R− не выводятся.

### Как ведут себя показания

* Показания только растут, как у настоящего счётчика. Сбросить их нельзя.
* Счёт начинается не с нуля, а с показаний счётчика, проработавшего
  1–4 года: от сотен тысяч (ТСН) до сотен миллионов (110 кВ) кВт·ч.
* Энергия считается в модельном времени. С `--time-scale 60` сутки
  потребления накапливаются за 24 минуты: так удобно быстро набрать
  данные для анализа. Метки времени в архиве SCADA при этом реальные.
* У каждого счётчика своя постоянная погрешность в пределах класса
  точности: A+ до ±0,3% (класс 0,5S), R+ до ±0,6% (класс 1).
  Поэтому баланс не сходится «в ноль», как и на реальном объекте.
* Показания сохраняются в `setpoints.json` каждые 10 секунд, а также
  при Ctrl+C и при закрытии окна exe. После перезапуска счёт продолжается
  с сохранённых значений. При аварийном завершении (снятие задачи,
  пропадание питания компьютера) теряется накопление максимум
  за последние 10 секунд.
* Учёт следует за схемой. Счётчик отключённого фидера стоит. После АВР
  `Meter.T1` и `Meter.In1` стоят, а `Meter.In2` считает нагрузку обеих секций.

### Что можно анализировать

Потребление за интервал равно разности показаний в конце и в начале
интервала (Δ). Типичные значения получены прогоном модели:

| Анализ | Формула | За сутки |
|---|---|---|
| Приём на ПС | ΔT1 + ΔT2 | 205 МВт·ч в июле … 250 МВт·ч в январе |
| Потери в трансформаторе | ΔT1 − ΔIn1 | 0,7–1,0%. При малой загрузке доля выше из-за потерь холостого хода |
| Небаланс секции | ΔIn1 − (ΔF1 + ΔF2 + ΔAux1) | В пределах ±0,6% (сумма погрешностей счётчиков) |
| Собственные нужды | ΔAux1 + ΔAux2 | 0,4–0,5 МВт·ч летом, около 0,9 МВт·ч зимой |
| Средний cos φ | ΔA / √(ΔA² + ΔR²) | 0,86–0,94 по фидерам |

Если за интервал срабатывал АВР или менялась схема, считайте баланс
по подстанции целиком: ΔIn1 + ΔIn2 = ΣΔF + ΔAux1 + ΔAux2.

Потребление зависит от дня недели (завод в выходные работает вполсилы)
и от сезона. Это видно на недельных и месячных трендах.

### Подсказки для SCADA

* Храните показания в Double (64 бита). У Float (32 бита) при показаниях
  50–150 млн кВт·ч шаг составляет 4–16 кВт·ч, и точность теряется.
* Для трендов потребления архивируйте показания раз в 1–30 минут,
  а почасовое или получасовое потребление считайте как разность соседних
  значений. Пропуски в архиве итог не искажают: разность за сутки
  всё равно будет точной.
* Для мгновенных графиков нагрузки удобнее `P` и `Q` фидеров и трансформаторов.

## Сценарии для проверки мнемосхемы

1. **Отключение/включение фидера.** Запишите `true` в `F1.CB.CmdOpen`:
   `F1.CB.State` станет 1, `F1.I` и `F1.P` упадут до 0, ток ввода `Sec1.InCB.I`
   уменьшится. Затем `F1.CB.CmdClose` включит фидер обратно, с броском тока.
2. **КЗ на линии.** `F2.SimFault = true` → `F2.I` 2–4 кА, `Sec1.U`
   проседает. Через 0,7 с МТЗ отключает выключатель: `F2.CB.State = 1`,
   `F2.Prot.Trip = true`, `Station.GeneralAlarm = true`.
   Повторное включение на КЗ снова отключит фидер. Дальше снимите
   `F2.SimFault`, выполните `Station.AlarmReset` и включите фидер.
3. **Потеря питания и АВР.** `VL1.SimLoss = true` → `VL1.U = 0`, Т1 обесточен,
   1 СШ без напряжения. Через 2 с отключается `Sec1.InCB`, включается `SecCB`,
   и обе секции питаются от Т2 (загрузка Т2 примерно удваивается,
   появляется `SecCB.I`). Восстановление: `VL1.SimLoss = false` →
   `SecCB.CmdOpen` → `Sec1.InCB.CmdClose` → `Station.AlarmReset`.
4. **Регулирование напряжения.** `T1.AVR.Uset = 10.8` → после выдержки
   `T1.AVR.Delay` РПН прибавляет ступени (`T1.Tap.InProgress`,
   `T1.Tap.Position`), пока `Sec1.U` не войдёт в зону. В ручном режиме
   (`T1.AVR.Auto = false`) работают `T1.Tap.CmdRaise` / `CmdLower`.
5. **Вывод трансформатора в ремонт.** `VL2.CB.CmdOpen` (сработает АВР) →
   `VL2.DS.CmdOpen` (около 6 с в промежуточном положении).
   Если сначала попытаться отключить разъединитель, команда будет отклонена
   блокировкой.
6. **Перегрев / обдув.** Запустите с `--time-scale 60`, переведите всю
   нагрузку на один трансформатор (сценарий 3). Ещё быстрее: понизьте
   `T1.Cooling.FanOnTemp` или `T1.Alarm.OilTempSet`.
7. **Местное управление.** `Station.RemoteMode = false` → любые команды
   отклоняются, горит `Station.GeneralWarning`.
8. **Анализ потребления.** Запустите с `--time-scale 60`: модельные сутки
   пройдут за 24 минуты. Настройте в SCADA архив `Meter.*.Aplus` раз
   в минуту и постройте почасовое потребление. Сравните ΔT1 и ΔIn1
   (потери), а также ΔIn1 и ΔF1 + ΔF2 + ΔAux1 (небаланс). Отключите фидер
   или вызовите АВР (сценарий 3), и учёт перейдёт на другой ввод.

## Подсказки для мнемосхемы

* **Аппараты.** Цвет задаётся по `*.State`: 1 — отключен, 2 — включен,
  0 — промежуточное (обычно мигание).
* **Окраска шин и линий под напряжением** — по `Sec1.U > 0`, `Sec2.U > 0`,
  `VL1.U > 0`, а для трансформатора — по `T1.U_LV > 0`.
  Обесточенные участки обычно выделяют серым.
* **Кнопки управления** пишут `true` в `CmdClose` / `CmdOpen`.
  Обратная связь идёт через `State`, сам `Cmd*` возвращается в `false`.
* **Контроль связи** — по `Station.Heartbeat`: если счётчик перестал
  расти, данные недостоверны.
* **Аварийные табло** — `Fx.Prot.Trip`, `ABR.Operated`,
  `T1.Alarm.*`, `Station.GeneralAlarm` / `GeneralWarning`.
  Кнопку «Квитировать» привяжите к `Station.AlarmReset`.

## Структура проекта

```
substation_emulator/
  tags.py      перечень тегов (типы, доступ, диапазоны, описания)
  model.py     физическая модель подстанции, без OPC UA
  server.py    OPC UA сервер (asyncua): адресное пространство, запись, события
  __main__.py  запуск из командной строки
tests/         тесты модели и интеграционные тесты через OPC UA клиент
tools/smoke_test.py         проверка работающего сервера (чтение + команды)
packaging/                  точка входа и скрипт сборки exe (PyInstaller)
.github/workflows/          автосборка exe на Windows и публикация в Releases
tags.csv       перечень тегов для импорта в SCADA
```

Как добавить фидер: допишите строку в словарь `FEEDERS` в `tags.py`.
Теги, модель, счётчик и адресное пространство подхватят его автоматически.

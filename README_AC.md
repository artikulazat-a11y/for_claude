# Эмулятор кондиционеров — Modbus TCP сервер

Имитатор 50 кондиционеров (инверторных сплит-систем) для отладки SCADA/BMS.
У каждого кондиционера свой Modbus TCP сервер на общем IP-адресе, но на своём
порту: **кондиционер №1 — порт 601, №2 — 602, …, №50 — 650**.

Кондиционер реагирует на включение и выключение, режим, уставку и скорость
вентилятора. Температура в помещении идёт к уставке, частота компрессора
и обороты вентилятора меняются в зависимости от того, насколько температура далека
от уставки. Случайная авария случается у каждого кондиционера не чаще раза в сутки
и держится до сброса.

## Быстрый старт

### Готовый exe для Windows (Python не нужен)

1. Скачайте **AirConditionerEmulator.exe** со страницы
   [Releases](https://github.com/artikulazat-a11y/for_claude/releases/latest).
2. Запустите двойным щелчком. В консоли видны подключения клиентов, команды
   и аварии («Кондиционер №7 (порт 607): АВАРИЯ E3 «Перегрев компрессора»»).
   Закрытие окна или Ctrl+C останавливает сервер.
3. Уставки, аварии и счётчики сохраняются в `ac_state.json` рядом с exe.

Windows SmartScreen при первом запуске может предупредить о неподписанной
программе: «Подробнее» → «Выполнить в любом случае». Брандмауэр спросит разрешение
на сетевой доступ: разрешите, если SCADA работает на другом компьютере
(входящие TCP 601–650).

### Из исходников

Нужен Python 3.10 или новее, сторонние библиотеки не нужны.

```bash
python -m ac_emulator
```

На Windows можно запустить `run_ac_emulator.bat`.

В Linux порты ниже 1024 открываются только от root: `sudo python -m ac_emulator`
или другие порты: `python -m ac_emulator --base-port 5601` (тогда 5601…5650).

### Параметры запуска

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--base-port` | 601 | Порт кондиционера №1. У кондиционера №N порт `base-port + N − 1` |
| `--count` | 50 | Число кондиционеров |
| `--host` | 0.0.0.0 | Адрес прослушивания (по умолчанию все сетевые интерфейсы) |
| `--time-scale` | 1 | Ускорение модели: `10` — помещения остывают и нагреваются в 10 раз быстрее. Ускоряет также погоду, счётчики энергии и наработки, задержку пуска компрессора. Случайные аварии и счётчик жизни идут по реальному времени |
| `--alarm-period` | 72 | Случайные аварии: наибольший интервал между авариями одного кондиционера, ч. Наименьший — всегда 24 ч |
| `--no-random-alarms` | — | Отключить случайные аварии (имитация аварии по команде работает) |
| `--state` | ac_state.json | Файл состояния (у exe — рядом с exe, иначе в текущей папке) |
| `--no-persist` | — | Не сохранять состояние: каждый запуск с начальных значений |
| `--seed` | — | Зерно случайных чисел для повторяемых прогонов |
| `--export-registers FILE` | — | Выгрузить карту регистров в CSV и выйти |
| `-v` | — | Подробный лог |

Готовая выгрузка лежит в репозитории: [`ac_registers.csv`](ac_registers.csv)
(UTF-8 с BOM, разделитель `;`, открывается в Excel).

## Адресация

* Одно устройство — один порт. Unit ID (Slave ID) в запросе может быть любым:
  ответ приходит с тем же Unit ID. Обычно в SCADA ставят 1.
* Адреса ниже даны **с нуля**, как они уходят в запросе Modbus. В нотации
  «4xxxx» регистр с адресом 0 — это 40001, катушка с адресом 0 — 00001,
  дискретный вход с адресом 0 — 10001.
* Holding- и Input-регистры — одна и та же таблица: её можно читать и функцией 3,
  и функцией 4. Запись — функциями 6 и 16.
* Всю таблицу удобно читать одним запросом: функция 3, адрес 0, 29 регистров.
  Адреса 6…9 зарезервированы и читаются как 0.

### Функции Modbus

| Код | Функция | Таблица |
|---|---|---|
| 1 | Read Coils | Катушки |
| 2 | Read Discrete Inputs | Дискретные входы |
| 3 | Read Holding Registers | Регистры |
| 4 | Read Input Registers | Регистры (та же таблица) |
| 5 | Write Single Coil | Катушки |
| 6 | Write Single Register | Регистры |
| 15 | Write Multiple Coils | Катушки |
| 16 | Write Multiple Registers | Регистры |

### Ошибки (исключения Modbus)

| Код | Когда |
|---|---|
| 01 Illegal Function | Функция не поддерживается |
| 02 Illegal Data Address | Адрес за пределами таблицы или запись в регистр только для чтения (в том числе резервный) |
| 03 Illegal Data Value | Значение вне диапазона (уставка 35 °C, режим 7) или неверное количество в запросе |

Групповая запись (функции 15, 16) выполняется целиком или не выполняется:
если хотя бы одно значение неверно, не меняется ничего.

### Типы данных

* `uint16`: целое 0…65535.
* `int16`: целое со знаком, дополнительный код. Температура −5,3 °C передаётся
  как −53 = 65483. В SCADA тип Int16 (Short), масштаб 0,1.
* `uint32`: два регистра, **старшее слово первым** (big-endian, порядок ABCD).
* Масштаб: значение = регистр × масштаб. Уставка 22,5 °C — это 225.

## Карта регистров (функции 3/4, запись 6/16)

### Управление

| Адрес | 4xxxx | Имя | Тип | Доступ | Масштаб | Диапазон / умолч. | Описание |
|---|---|---|---|---|---|---|---|
| 0 | 40001 | `Power` | uint16 | **W** | | 0…1 / 1 | Питание: 0 — выключить, 1 — включить |
| 1 | 40002 | `Mode` | uint16 | **W** | | 0…3 / 0 | Режим: 0 — авто, 1 — охлаждение, 2 — нагрев, 3 — вентиляция |
| 2 | 40003 | `Setpoint` | int16 | **W** | 0,1 °C | 16,0…30,0 / 22,0 | Уставка температуры воздуха в помещении |
| 3 | 40004 | `FanMode` | uint16 | **W** | | 0…3 / 0 | Скорость вентилятора: 0 — авто, 1 — низкая, 2 — средняя, 3 — высокая |
| 4 | 40005 | `AlarmReset` | uint16 | **CMD** | | 0…1 | Сброс аварии: записать 1 |
| 5 | 40006 | `SimAlarm` | uint16 | **CMD** | | 0…8 | Имитация аварии: записать код аварии 1…8 |

**W** — уставка: читается и пишется, сохраняется между перезапусками.
**CMD** — команда: исполняется сразу при записи, при чтении всегда 0.

### Состояние и измерения (только чтение)

| Адрес | 4xxxx | Имя | Тип | Масштаб | Ед. | Описание |
|---|---|---|---|---|---|---|
| 10 | 40011 | `State` | uint16 | | | Состояние, см. ниже |
| 11 | 40012 | `Status` | uint16 | | | Слово состояния (биты), см. ниже |
| 12 | 40013 | `RoomTemp` | int16 | 0,1 | °C | Температура воздуха в помещении |
| 13 | 40014 | `SupplyTemp` | int16 | 0,1 | °C | Температура воздуха на выходе внутреннего блока |
| 14 | 40015 | `OutdoorTemp` | int16 | 0,1 | °C | Температура наружного воздуха |
| 15 | 40016 | `FanSpeed` | uint16 | | об/мин | Скорость вращения вентилятора внутреннего блока |
| 16 | 40017 | `FanLevel` | uint16 | | | Текущая ступень вентилятора: 0 — стоит, 1 — низкая, 2 — средняя, 3 — высокая |
| 17 | 40018 | `CompressorFreq` | uint16 | | Гц | Частота компрессора (0 — стоит) |
| 18 | 40019 | `PowerInput` | uint16 | | Вт | Потребляемая мощность |
| 19 | 40020 | `AlarmCode` | uint16 | | | Код активной аварии (0 — нет аварии) |
| 20 | 40021 | `LastAlarmCode` | uint16 | | | Код последней аварии (остаётся после сброса) |
| 21 | 40022 | `AlarmCount` | uint16 | | | Счётчик аварий |
| 22–23 | 40023 | `Energy` | uint32 | 0,1 | кВт·ч | Потреблённая электроэнергия нарастающим итогом |
| 24–25 | 40025 | `RunHours` | uint32 | | ч | Наработка (время работы вентилятора) |
| 26 | 40027 | `Heartbeat` | uint16 | | | Счётчик жизни, +1 каждую секунду (после 65535 — 0) |
| 27 | 40028 | `DeviceNumber` | uint16 | | | Номер кондиционера 1…50: проверка, что опрашивается нужный порт |
| 28 | 40029 | `Capacity` | uint16 | | Вт | Номинальная холодопроизводительность |

#### Состояние `State`

| Значение | Состояние |
|---|---|
| 0 | Выключен |
| 1 | Охлаждение (компрессор работает) |
| 2 | Нагрев (компрессор работает) |
| 3 | Вентиляция |
| 4 | Ожидание: уставка достигнута, компрессор на паузе, или идёт задержка пуска компрессора |
| 5 | Авария |

#### Слово состояния `Status`

| Бит | Маска | Значение |
|---|---|---|
| 0 | 1 | Питание включено (команда) |
| 1 | 2 | Кондиционер работает (включён и нет аварии) |
| 2 | 4 | Компрессор работает |
| 3 | 8 | Авария |
| 4 | 16 | Уставка достигнута (±1 °C) |
| 5 | 32 | Задержка пуска компрессора (защита от частых пусков) |
| 6 | 64 | Действующий режим — нагрев (в режиме «авто» показывает, что выбрал кондиционер) |

### Катушки (функции 1/5/15)

| Адрес | 0xxxx | Имя | Описание |
|---|---|---|---|
| 0 | 00001 | `Power` | Питание: то же, что регистр `Power` |
| 1 | 00002 | `AlarmReset` | Сброс аварии: записать 1 (читается как 0) |

### Дискретные входы (функция 2)

| Адрес | 1xxxx | Имя | Описание |
|---|---|---|---|
| 0 | 10001 | `Running` | Кондиционер работает |
| 1 | 10002 | `Compressor` | Компрессор работает |
| 2 | 10003 | `Alarm` | Авария |
| 3 | 10004 | `SetpointReached` | Уставка достигнута (±1 °C) |

### Коды аварий

| Код | Обозначение | Авария | Когда бывает |
|---|---|---|---|
| 1 | E1 | Высокое давление в контуре хладагента | только при работе |
| 2 | E2 | Низкое давление, утечка хладагента | только при работе |
| 3 | E3 | Перегрев компрессора | только при работе |
| 4 | E4 | Неисправность вентилятора внутреннего блока | только при работе |
| 5 | E5 | Неисправность датчика температуры воздуха | всегда |
| 6 | E6 | Нет связи с наружным блоком | всегда |
| 7 | E7 | Переполнение дренажного поддона | только при работе |
| 8 | E8 | Напряжение питания вне допуска | всегда |

## Что моделируется

* **Помещение.** Каждый кондиционер обслуживает своё помещение. Помещение
  нагревается от людей и техники (в рабочее время по будням сильнее, ночью
  вдвое слабее) и обменивается теплом с улицей и соседними помещениями.
  При выключенном кондиционере температура уходит к своему равновесию: летом
  днём 28–36 °C, ночью 22–26 °C, зимней ночью 16–21 °C (здание отапливается).
* **Паспорт.** Холодопроизводительность 2,5 / 3,5 / 5,0 / 7,0 кВт, размер
  помещения и тепловыделения у каждого номера свои. Они не меняются между
  запусками: кондиционер №7 всегда один и тот же.
* **Погода.** Температура наружного воздуха общая для всех: по сезону
  (средняя полоса) и времени суток, с медленными случайными колебаниями.
* **Компрессор (инвертор)** работает от 20 до 90 Гц. Частоту задаёт
  ПИ-регулятор по отклонению температуры от уставки: чем дальше, тем выше
  частота. У уставки частота снижается до той, что нужна для поддержания
  температуры. Пуск — при отклонении больше 0,5 °C, останов — при
  переохлаждении (перегреве) на 0,8 °C. При малой нагрузке компрессор работает
  циклами. После останова повторный пуск не раньше чем через 60 с
  (бит 5 `Status`), так же и после сброса аварии.
* **Вентилятор.** В режиме «авто»: высокая скорость при отклонении от уставки
  больше 2 °C, средняя — больше 1 °C, низкая — у уставки (переход вниз с
  гистерезисом 0,3 °C). Обороты: низкая ~650, средняя ~900, высокая
  ~1150 об/мин (у каждого экземпляра ±3%). Обороты меняются плавно, около
  150 об/мин за секунду, при выключении вентилятор выбегает до нуля.
  Ручная скорость (`FanMode` 1…3) держится постоянной.
* **Режимы.** «Охлаждение» и «нагрев» работают только в свою сторону: если
  в помещении холоднее уставки, в режиме охлаждения компрессор стоит
  (`State` = 4). «Авто» сам выбирает охлаждение или нагрев: переключается,
  когда температура уходит от уставки больше чем на 1,5 °C в другую сторону.
  «Вентиляция» — только вентилятор (в режиме «авто» скорость средняя).
* **Воздух на выходе** холоднее (теплее) комнатного на 5–10 °C при работе
  компрессора и возвращается к комнатной, когда компрессор стоит.
* **Потребляемая мощность** считается по производительности и холодильному
  коэффициенту (COP 2–5,5: ниже при высокой частоте и жаре на улице, при
  нагреве — в мороз), плюс вентилятор и электроника (4 Вт в выключенном
  состоянии).
* **Счётчики** энергии и наработки только растут. Счёт начинается не с нуля,
  а как у кондиционера, отработавшего 1500–20 000 ч.

## Аварии

### Случайные аварии

* У каждого кондиционера в случайный момент случается случайная авария из
  таблицы кодов. Если кондиционер выключен, выбирается авария, которая бывает
  и без работы (E5, E6, E8).
* Между двумя случайными авариями одного кондиционера проходит **не меньше
  24 часов**: случайный интервал от 24 до 72 часов (верхняя граница —
  `--alarm-period`). В среднем это одна авария за двое суток на кондиционер,
  а на все 50 — около 25 аварий в сутки, примерно одна в час.
* Первая авария после запуска приходит в случайный момент в пределах
  `--alarm-period`.
* Расписание сохраняется в `ac_state.json`, поэтому перезапуск эмулятора
  не приводит к лишней аварии раньше суток.
* Пока авария не сброшена, новая случайная не появляется: она откладывается
  на 0,5–3 часа после сброса предыдущей.
* Имитация аварии командой (`SimAlarm`) в этот счёт не входит.

### Что происходит при аварии

* `State` = 5, `AlarmCode` = код аварии, бит 3 `Status` и дискретный вход
  `Alarm` = 1, увеличивается `AlarmCount`.
* Компрессор сразу останавливается, вентилятор выбегает до нуля, помещение
  начинает нагреваться (остывать).
* Команда `Power` остаётся как была: выключение и включение аварию не сбрасывают.
  Уставки можно менять и во время аварии.

### Сброс аварии

Записать 1 в регистр `AlarmReset` (адрес 4, 40005) или в катушку `AlarmReset`
(адрес 1, 00002). `AlarmCode` станет 0, `LastAlarmCode` сохранит код.
Если кондиционер включён, вентилятор запускается сразу, компрессор — после
задержки пуска, если с его останова прошло меньше 60 с.

## Сохранение состояния

В `ac_state.json` хранятся для каждого кондиционера: питание, режим, уставка,
скорость вентилятора, активная авария, последняя авария, счётчик аварий,
энергия, наработка и время следующей случайной аварии. Уставки и аварии
сохраняются сразу после изменения, счётчики — каждые 10 секунд, а также
при Ctrl+C и закрытии окна exe. После перезапуска кондиционеры продолжают
с сохранённых значений, помещение — сразу в установившемся режиме.

## Сценарии для проверки SCADA

1. **Связь и адресация.** Опросите `DeviceNumber` (адрес 27) на портах 601…650:
   должно прийти 1…50. `Heartbeat` (адрес 26) растёт каждую секунду.
2. **Выключение и включение.** `Power` = 0: `State` = 0, обороты
   вентилятора плавно падают до 0, частота компрессора 0, мощность — 4 Вт.
   Температура в помещении начинает расти (летом). `Power` = 1: вентилятор
   разгоняется, при отклонении больше 0,5 °C запускается компрессор.
3. **Уставка.** Понизьте `Setpoint` на 4 °C (например, 180 = 18,0 °C):
   вентилятор переходит на высокую скорость (~1150 об/мин), частота компрессора
   растёт до 85–90 Гц, воздух на выходе холоднее комнатного примерно на 9 °C,
   мощность растёт в несколько раз. За 5–10 минут температура подходит
   к уставке, вентилятор сбавляет до низкой скорости, частота падает до 30–60 Гц.
   Чтобы не ждать, запустите с `--time-scale 10`.
4. **Нагрев.** `Mode` = 2 и `Setpoint` выше температуры в помещении:
   `State` = 2, воздух на выходе теплее комнатного.
5. **Авария.** Запишите 3 в `SimAlarm`: `State` = 5, `AlarmCode` = 3
   (E3 «Перегрев компрессора»). Сброс — 1 в `AlarmReset`.
6. **Случайные аварии.** Оставьте эмулятор работать на час-два: у кого-нибудь
   из 50 кондиционеров появится авария. В журнале консоли видно, у какого.
7. **Ошибки записи.** Уставка 35 °C (350) или режим 7 — исключение 03,
   запись в `RoomTemp` — исключение 02. Значение не меняется.

## Структура

```
ac_emulator/
  registers.py  карта регистров, коды аварий, выгрузка CSV
  model.py      модель кондиционеров и помещений, случайные аварии (без Modbus)
  modbus.py     Modbus TCP сервер на asyncio (без внешних библиотек)
  server.py     50 серверов на портах подряд, журнал, сохранение состояния
  __main__.py   запуск из командной строки
tests/test_ac_*.py        тесты модели и интеграционные через клиент pymodbus
tools/ac_smoke_test.py    проверка работающего эмулятора (без сторонних библиотек)
packaging/ac_entry.py     точка входа для сборки exe (PyInstaller)
ac_registers.csv          карта регистров для импорта в SCADA
```

Проверка запущенного эмулятора: `python tools/ac_smoke_test.py 127.0.0.1 601 50`.

Тесты:

```bash
pip install -r requirements-dev.txt
python -m pytest
```
